# 按成本加价工作台（2026-09-15）

本轮在 `dev` 开发，未部署、未修改生产价格、未向真实 new-api 发出价格写入或收费请求。

## 操作流程

入口仍为 `/admin/pricing`，新增「按成本加价」。

1. 选择模型和已登记档次，填写上游参考价、上游倍率及自己的加价比例。
2. 报价以人民币计时不再做额度兑换；报价以供应商账户额度计时，填写「每充值 1 元到账额度」。参考价已经包含上游倍率时，倍率明确填 `1`，避免重复计算。
3. 核对试算，再「保存成本规则」。这一步只存报价资料，不改变客户售价。
4. 勾选已保存规则；可统一修改加价比例并保存，然后「预览所选价格」。
5. 预览会展示所有受影响的模型与档次。确认后产生持久发布任务；只有任务显示「已生效」，才表示 new-api 实时配置与持久数据库已核验，且目录价格已更新。

计算规则：

```text
报价成本 = 上游参考价 × 上游倍率 ÷ 每元到账额度
计划售价 = 报价成本 × (1 + 加价百分比 / 100)
毛利率   = (计划售价 - 报价成本) / 计划售价
```

人民币来源的兑换因子为 `1`。例如成本 ¥1，加价 20%，计划售价为 ¥1.2、毛利率约 16.67%，不是 20%。试算没有包含支付手续费、退款及未录入的上游收费。

## 当前支持范围

| 类型                              | 成本记录和试算                                       | 发布                                                                        |
| --------------------------------- | ---------------------------------------------------- | --------------------------------------------------------------------------- |
| 普通文字模型                      | 输入、输出、可选缓存读写，按百万 token               | 输入输出可发布；配置缓存报价时暂阻止整条规则发布，避免静默忽略缓存售价      |
| 普通按次图片模型                  | 按张、可记录规格                                     | 已配置的普通单一按次价格可发布；不能将一条 ModelPrice 冒充多个分辨率价格    |
| 固定图片 `gpt-image-2-{1k,2k,4k}` | 对应独立分辨率的每张成本及张数试算                   | 专用成本流程可发布已配置同名 SKU；不改变尺寸和渠道映射                      |
| 视频                              | 分辨率、声音、参考视频、每秒报价、最低秒数、计费步长 | 可保存和试算，尚未接通视频真实价格发布；不将按 token 或按任务收费强改为按秒 |

缓存未提供不代表免费。未独立发布缓存价格的文字模型，仍遵循 new-api 现有缓存倍率，输入基础倍率的变化可能影响实际缓存费用；预览会提示这一限制。

视频最低计量采用 `minimum + ceil((units - minimum) / step) × step`（用量低于最低值时按最低值；用量为零时为零）。不同供应商的取整方式仍须由维护人员确认；这里只用于报价试算。

new-api 的同名模型基础价格跨档次共享。一批所选档次如推导出互相矛盾的基础倍率，会拒绝发布并提示核对，不能保证每个档次的独立利润目标都能同时实现。其他未选中的关联档次也会列在预览影响范围中。

「旧版参考成本」入口保留，但明确说明它只更新旧目录的参考成本，不生成售价，也不更新新工作台的完整报价规则。新工作台完整成本分别记录，发布时不清空既有单列参考成本。

## 实现与安全边界

- 新增 `pricing_cost_rules` 与 `pricing_cost_rule_revisions`，按模型和档次唯一保存；精确绑定渠道 ID 和上游模型名。保存成本不会写 `CatalogPrice`、API Key、余额或 new-api。
- 每次保存同一事务追加版本快照；数据库触发器禁止覆盖历史快照。模型删除时，所属草稿与快照按外键级联删除。
- 保存要求 `expected_revision` 匹配，并取得既有发布协调锁。并发编辑只有一个能成功；批量保存最多 30 条，一条失败整批回滚。
- 发布金额由服务端按保存规则推导，不接受前端自行给出的计算结果。规则、版本、映射、所选规格与操作者绑定预览签名；修改后必须重新预览。
- 入队、每次写前及目录生效前，检查保存的成本上下文。发布进行中或有未解决任务时，成本修改也被协调锁阻止。
- 新 v2 发布任务合并每个配置字典的目标，每个字典最多一次 PUT，继续使用写入日志、实时/持久双读、不确定写入阻断及失败恢复。所有目录行仅在整批核验完成后同一事务生效。
- 保持 v1 任务签名与恢复语义。原通用入口仍拒绝固定 SKU，只有成本流程的明确模式才允许调整已有独立 SKU。
- 多字典写入不是 new-api 的原子事务：输入输出字典切换间仍可能短暂使用混合倍率。不能把 Portal 目录原子更新描述为客户请求期间绝无过渡价。
- 能力提示仅表示当前读取的计费规则可表达。确认预览仍强制检查持久数据库；读取失败不降级成“发布成功”。
- 未改 new-api 源码、路由算法、供应商调用链、尺寸规则、Nginx/Cloudflare 或运行环境变量。
