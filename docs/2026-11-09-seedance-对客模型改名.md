# Seedance 四个模型改名（只改展示名）

> 状态：进行中
>
> 日期：2026-11-09。起因：operator 担心对客用字节的 `doubao-seedance-*` 有侵权风险。

## 1. 需求与结论

需求是把对客的 `doubao-seedance-*` 换掉。**结论：只改展示名，API 模型名保持不变**，因为换 API 名被 new-api 的插件机制挡住（见第 3 节）。

operator 先后选过「照抄上游名 `artsdance-*`」和「只改展示名」，最终定第二种。

## 2. 三层名字的现状

渠道 13「官转SD」，`type=65`（Task Plugin，绑 doubao 插件），`base_url=https://token.xinhankr.com`，分组 `SD官转`，`GroupRatio=7.5`。

| 对客名（客户 API 里填的） | 渠道重定向后发给上游 |
| --- | --- |
| `doubao-seedance-2-0-260128` | `artsdance-2-0-pro-260801` |
| `doubao-seedance-2-0-fast-260128` | `artsdance-2-0-fast-260801` |
| `doubao-seedance-2-0-mini-260615` | `artsdance-2-0-mini-260801` |
| `doubao-seedance-2-5-260628` | `artsdance-2-5-pro-260801` |

上游 xinhankr 自己已经避开了品牌词：`doubao-seedance` → `artsdance`，删掉「doubao」、把「seedance」改一个音节，档位名和版本号保留，日期统一写 `260801`。

## 3. 为什么换不了 API 名（实测阻塞）

参数矩阵公式引用的 `u("resolution")`、`u("video_input")`、`u("tokens")` 来自**渠道绑定的 Task Plugin 声明的 usage schema**。doubao 插件在源码 `plugins/tasks/doubao/plugin.js` 的 `meta.models` 里把模型名写死，只有列表内的名字有 schema。

给 `artsdance-2-0-fast-260801` 配同样的公式时，new-api 直接拒绝：

```
模型 artsdance-2-0-fast-260801 的计费表达式无效:
expression references usage keys [resolution tokens video_input]
but the model has no task plugin usage schema
```

所以**对客名必须是插件声明的名字之一**。2026-10-29 当初配成「对客 doubao 名 → 上游 artsdance 名」不是任意选择，是被插件逼的。

出路只有三条：改插件源码（CLAUDE.md 明令禁止，AGPL）、自写 Task Plugin 声明新名（要重新实现提交/查询/用量上报/成片解析，且插件接口 v1 未正式发布）、或只改展示名。选第三条。

## 4. 本次执行记录

尝试过第 1 步「给 artsdance-* 复制计费配置」，**两次失败，生产未留任何改动**：

1. 先写 `billing_mode` 后写 `billing_expr` → `billing expression is required`。new-api 校验设成 `tiered_expr` 的模型必须已有公式，所以必须**先写公式再写模式**。
2. 调整顺序后重试 → 撞上第 3 节的 usage schema 阻塞。

核实未写入：`billing_expr` 15 条、`billing_mode` 78 条均无 `artsdance` 键，旧名四条公式完好，渠道 13 的 `models` 未变。

## 5. 顺带发现：计费配置不能只读数据库

`billing_setting.billing_expr` 在 `options` 表那一行里是 **12 条**，但 `GET /api/option/` 返回 **15 条** —— 多出 `gpt-image-2`、`gpt-image-2.5-flare`、`gpt-image-2.5-sunburst` 三个图片模型。运行配置里有、数据库那一行里没有。

**查计费配置要用 API，只读数据库会漏。** 本仓之前的只读核对如果只查了 `options` 表，可能低估过条目数。

## 6. 要改的展示名

`catalog_models.display_name`，只影响 Portal 页面展示（`/models`、`/pricing`、定价页、模型广场），不影响 API 调用。同步目录时按 slug 自动生成，现在是：

| slug | 自动生成的显示名（现） |
| --- | --- |
| `doubao-seedance-2-0-260128` | Doubao Seedance 2 0 260128 |
| `doubao-seedance-2-0-fast-260128` | Doubao Seedance 2 0 Fast 260128 |
| `doubao-seedance-2-0-mini-260615` | Doubao Seedance 2 0 Mini 260615 |
| `doubao-seedance-2-5-260628` | Doubao Seedance 2 5 260628 |

`vendor` 四个都是 `unknown`（`inferVendor` 认不出 `doubao-` 前缀），模型广场的厂商筛选里归「未知」。

**待 operator 定**：新显示名用什么写法，`vendor` 填什么。改法是在 `/admin/models` 逐个改（需 superadmin 登录态）。

## 7. 未决问题

1. 新显示名和 `vendor` 的具体取值。
2. `inferVendor` 要不要加一条规则避免新同类模型再出现 `unknown`；若新显示名不想暴露上游，`vendor` 也不宜填上游名。
3. API 名长期保持 `doubao-seedance-*` 是否接受。彻底更换需自写 Task Plugin，建议另起文档评估。
