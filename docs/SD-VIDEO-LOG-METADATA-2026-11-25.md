# SD 特惠日志元数据改造（2026-11-25）

## 当前状态

本文记录视频日志展示、计费和交付数据的来源，以及生产切换前的验证条件。真实样本验收选用已生成的历史任务。

本轮不修改 new-api 源码、模型路由、客户售价、采购成本或扣费逻辑。

## 展示变化

- 概览「调用明细」、调用日志页与 CSV 将已知内部 SKU 显示为对应公开模型，例如 `sd-2-mini-480-novideo` 显示为 `sd-2-mini`。
- 分辨率、参考视频状态仍在视频明细中显示；有记录时额外显示「请求画幅」和「任务耗时（含排队）」。中英文均支持。
- 按秒记录缺少任务时间时，列表显示 `—`、CSV 留空，不使用提交接口的 HTTP 耗时冒充任务耗时。
- 按秒不伪造 tokens，现有金额、历史单价核对、失败退款配对、错误脱敏和用户隔离规则保持。
- 本轮范围是 `/dashboard` 的调用明细、`/logs`、对应日志 API 与 CSV，不改统计卡片、聚合和计费口径。
- 两处明细显示生成状态、进度、任务时间、成片时长与安全请求参数摘要。生成状态来自任务记录，扣费阶段仍来自账单。
- 已完成的任务可预览、下载。播放器使用 Portal 会话鉴权及当前任务归属，媒体地址只在服务端使用。

示例：有完整快照的 `sd-2-mini` 任务可同时显示 `480p · 无参考视频 · 4 秒`、请求画幅 `16:9`、任务耗时 `3m 27s`。

## 概览同步

概览此前是独立的日志转换与表格组件，没有接入全部日志页的视频解析。本次补齐后，两处复用 `parseVideoTaskBilling`、`enrichSdSpecialVideoLogs` 和同一个 `VideoBillingDetail` 展示组件。

- 模型下方显示分辨率、参考状态、计费秒数和扣费阶段；点击视频结果按钮展开任务信息、单价与计费公式。
- 特惠按秒不展示噪声 tokens；官转视频展示日志中的计费 tokens，即使原始输入/输出 token 列为空。
- 特惠任务耗时按用户限定读取终态任务记录，缺失时仍显示 `—`，不拿提交 HTTP 耗时代替；历史画幅没有快照仍保持未知。
- 官转耗时直接读取任务提交与结束时间，筛选和翻页后的单条结算记录也能显示。
- 保留原有日志缓存、有界查询、最多 200 行、每页 20 行、退款配对、负额结算退款、错误脱敏与用户二次过滤；不改变余额和聚合。
- 两类元数据读取故障分别降级，不能让缺少画幅或时间影响账单显示。按秒扣费阶段不代表任务已经生成成功。

## 简名筛选与分页

new-api 的模型日志过滤是精确匹配，不能只替换展示名。公开简名查询会展开成当前已登记的确切 SKU，分别查询，再按日志 ID 降序归并、按全局页大小分页。

- `sd-2.5` 不包含 `sd-2.5-flash`；不同分辨率、参考状态的记录都参与同一次筛选。
- 同名共用的 1080p SKU 去重；未识别的型号不按模糊前缀归类。
- 普通模型查询及手动输入确切 SKU 的查询保持原行为。
- 若上游忽略精确模型过滤，查询报错，不把其他模型混入结果。
- HTTP CSV 复用归并迭代器，保留 10,000 原始行上限与截断提示；日志库直连仍用 keyset 流式导出。
- CSV 保留原有前 12 列位置，附加计费方式、规格、计费秒数、任务耗时、生成状态、成片时长、任务时间和安全参数摘要。媒体探测只在打开任务明细时按需执行，大批量导出只取任务库已确认的成片时长。

## 数据来源与安全边界

### 提交快照

新增 Portal 表 `sd_video_task_metadata`，保存任务与 Portal 用户关联以及白名单请求参数，包括已记录的分辨率、参考视频标记、画幅、时长、随机种子、生成音频和水印选项。

- 不保存 API Key、prompt、素材 URL、供应商凭据或金额。
- 只在 new-api 已成功返回合法任务 ID 后，以 Key 关联的 Portal 用户身份保存。
- 事务写入、任务 ID 唯一，重复任务不覆盖原账号或原规格。
- 保存失败仅降级为缺少元数据，不改变已受理响应，不重发生成请求。
- 请求未传画幅或画幅不在已知枚举内时保存空值，不默认补 `16:9`。

### 任务耗时

沿用 `NEWAPI_SD_VIDEO_DELIVERY_DATABASE_URL`，添加只读视图 `portal_sd_video.customer_tasks`，仅纳入 SD 特惠和官转任务。查询按当前 new-api 用户 ID 和任务 ID 批量关联，每批最多 500 个任务。现有 `delivery_tasks` 继续服务原接口和特惠历史耗时兜底。

耗时 = new-api 任务 `finish_time - submit_time`，包含排队和任务状态同步。只有任务到达终态且时间有效时才显示耗时。

官转使用成功响应里的成片时长。已核对的特惠历史数据以请求时长填充计量字段，Portal 展开明细时使用最多 256 KiB 的 MP4 文件头探测实际时长。浏览器播放时也可读取视频元数据。文件过期或头部缺失时，相应成片字段保留为空。

预览与下载均验证活动会话和当前账号的任务归属。媒体读取使用已确认的来源或当前任务的受控缓存路径，支持 Range 区间读取，返回私有且不可缓存的 MP4 流。

已有成功样本中，new-api 的任务时间差为 207 秒，供应商记录为 186 秒；两者口径不同，不把 207 秒标成供应商纯生成时间。本轮未重新付费生成该样本。

### 读取与历史兼容

- 快照按 Portal 用户 ID 读取；任务时间按 new-api 用户 ID 读取。两者还需匹配当前模型，禁止跨账号或跨模型补数据。
- 日志已有的规格事实优先，快照只补缺失值；耗时来自任务终态时间，不参与费用计算。
- 1080p 共用 SKU 不能证明带了参考视频；有快照按真实请求显示，无快照且日志未记录时维持未知。
- 历史任务可以通过现有视图补时间，但没有原始画幅快照的历史记录仍不显示画幅，不从成片尺寸或轮询时间猜测。
- 快照表或只读任务库不可用时独立降级，保留原账单。失败退款已配对的预扣行不导出扣费明细。
