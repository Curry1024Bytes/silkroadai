# Portal 定价发布改造（2026-09-12）

本轮由 operator 批准开发，工作分支为 `dev`，基于 `82a3212`。没有同步新上游、改动 `main`、部署 VPS，或提交任何真实改价。当前生产仍运行此前目录同步版本。

## 解决的问题

旧定价保存先写入已经生效的 `CatalogPrice`，再尽力调用 new-api；写失败仍返回 201。文本的输入、输出倍率又是两次独立 PUT，可能只写成功一项。旧“重新同步”还会自动选一个档次写入全局价格，其他同名档次可能随之改价而目录未更新。

现在采用“预览全部影响 → 保存持久发布任务 → 写入与核验 → 目录生效”。new-api 继续执行真实扣费；Portal 没有启用独立扣费、模型路由或直接调用供应商。

## 已实现的行为

- **预览**：选定明确的模型和档次，列出全实例所有使用同一个 new-api 模型名的目录模型及档次，显示旧目录价和新价。客户专属倍率另有说明。预览不修改价格。
- **确认**：十分钟签名绑定管理员、输入、完整目录与渠道/计费配置、金额换算单位。配置或输入变化必须重新预览；同一确认重发返回原任务，不能重复发布。
- **持久任务**：确认只返回 202 和任务，关闭页面或 Portal 重启不会丢失已提交任务。后台调度器每十秒检查，连接或已确认写入后的核验失败最多自动尝试六次，之后明确暂停；重试先读状态，只补未完成部分。
- **真实保存核验**：同时读取 new-api 管理 API 与其实际 MySQL 的四个价格选项；都必须与目标一致，并核对分组、渠道和实际输出倍率元数据。缺少专用只读连接、价格缺项、运行值与保存值不一致时，不能降级成尽力写入或成功提示。
- **持久写入日志**：每次 PUT 前独立提交 `in_flight`，明确成功响应后独立提交 `acknowledged`。HTTP 200 的 HTML、缺少成功 envelope、连接中断不算确认。
- **不确定结果**：未确认请求可能在服务器晚到执行，不能仅凭双读推断已结束。任务保留全局锁、暂停补写/成功/取消，必须由维护人员确认旧执行者与旧请求均不再执行，并通过有审计记录的工具解封。参见 [未决写入恢复](PRICING-PUBLISH-UNCERTAIN-WRITES.md)。
- **统一生效**：核验通过后，一次 Portal 事务新增全部受影响目录价格、写成功状态并释放任务锁；任何目录插入失败整批回滚。旧价格历史不删除，其他档次的成本保留，当前编辑档成本按预览表单保存。
- **目录刷新**：SDK 模型目录每次先读共享版本，发布事务提交后下一次请求刷新价格，不等待进程内六十秒缓存过期。当前空闲 worker 每十秒也会推进协调版本，缓存有效期通常会缩短到约十秒；这是额外读库开销，不改变模型列表与鉴权规则。
- **并发保护**：按整个 new-api 实例使用 PostgreSQL 协调行锁。目录导入、批量成本、模型/档次 CRUD、渠道替换、后台分组对账及客户倍率保存/停用与发布互斥，不能在中途改掉预览依据。存量 Key 迁移保留原来的事务与补偿路径。
- **界面方向**：模型/档次入口叫“从 new-api 更新目录”；定价入口叫“发布价格到 new-api”。旧目录记录和发布任务核验状态分开展示，只有任务 `succeeded` 显示“已生效”。旧无预览的直接保存及旧 resync API 返回 409 指引。

## 计费保护和兼容范围

1. 本轮仅支持既有普通按 Token/按次计费方式，不隐式切换计费方式。阶梯、定时折扣、分辨率覆盖或类型不匹配必须先核对。固定 `gpt-image-2-{1k,2k,4k}` 及其共享引用不得通用改价；三个既有固定价格没有修改。
2. 输入/输出价使用未舍入基数分别换算后再保留四位小数，修正旧逆换算先舍入输入再乘输出倍率的问题。例如 `CHAT_FX=14.4, mr=0.00001, cr=10, group=1`，输出目录价应为 `0.0014`，原来会错误显示 `0.0010`。
3. 金额上限对应现有 `Decimal(12,4)`。Token 输入价须大于零；拒绝正数换算成零、缺失分组倍率、未来生效目录价被覆盖、渠道失效与硬编码输出倍率不符。
4. 用户专属 `GroupGroupRatio` 不会被本任务修改；公共目录展示标准档次价，不冒充每个客户的最终实扣。缓存、音频等额外计费维度仍按 new-api 的既有设置执行，本表不是完整账单模拟器。
5. new-api 管理 API 没有通用批量事务或 CAS。**两次 PUT 之间仍可能短暂使用一新一旧的倍率，当前实现不暂停客户请求。**发布期间不得同时在 new-api 后台或独立脚本改价；此约定不能被 Portal 单方面技术强制。发现变化会停止，不会把旧全表快照覆盖回去。
6. `succeeded` 证明发布时核验的运行值、保存值和目录一致，不承诺此后被其他工具修改仍永久一致，也不保证 new-api 不可用时立即完成。

## 数据库、依赖与运维变化

- Portal migration `20260912040000_add_pricing_publications` 新增 `pricing_publish_jobs`、`pricing_publish_coordinator`、`pricing_publish_writes` 三表及索引；不回填或删除现有客户、模型、价格、订单数据。即使不启用调度器，也必须先迁移，目录写入口已经使用协调表。
- 增加 `@prisma/adapter-mariadb@7.4.1` 和独立只读 Prisma schema/client，只映射 new-api 既有 `options` 表。只能运行 client generate，禁止对该 schema 执行 migrate/db push。生成配置故意不读取实际只读连接串。
- `pnpm prisma:generate` 生成两个客户端，构建及 CI 已接入；没有升级原有 Prisma/Next.js 等锁定版本。生产镜像仍由干净 Git 归档构建，排除 `.env*` 与运行时信任材料。
- 新增可选 `NEWAPI_PRICING_DATABASE_URL`、`NEWAPI_PRICING_RSA_PUBLIC_KEY_FILE`。专用数据库账号只应有目标 `options` 表 SELECT 权限，不使用 root 或 new-api 写账号，不公开 MySQL 端口。可以使用受信任 TLS，或 Docker 内网经核验的固定服务端 RSA 公钥，禁止自动获取陌生公钥。
- Portal Compose 增加 `deploy/runtime/newapi-pricing` → `/app/newapi-pricing:ro` 挂载，只放公开信任材料，不放密码；目录被 Git/Docker 构建忽略。现有 `newapi-net` 和默认网关优先级保留，未增加公开端口或新服务。
- PostgreSQL 连接池需要至少两条可用连接：一条持有发布事务，另一条独立持久化写入日志，并应为正常请求预留余量。调度器继续遵守 `PORTAL_SCHEDULERS=off` 与 Enterprise 实例隔离。
- 实际本机 `.env`、IDE 配置及用户已有未跟踪需求文档保留；生产账号、配置、价格、服务均未修改。
