## 模型广场：结论与已确认差异

可以采用上游的卡片、表格、搜索筛选、详情和性能展示，同时继续使用 LLmRoute 的目录与报价规则。已审查的广场客户端 API 仅导出 GET，Portal 代理白名单只有 pricing 与两类 perf-metrics 路径；未发现其直接写入渠道、创建 Key、充值或扣费的请求。真正需要适配的是读取和展示语义。

### 1. 目录来源不同

当前 `src/lib/models/catalog-browser.ts` 的 `loadBrowserCatalog` 从平台租户的启用 CatalogModel、ChannelGroup 和生效 CatalogPrice 读取数据，排除 HIDDEN_MODELS，并验证模型与档次/渠道归属。分组语义包括十月已经上线的镜像模式，不能退回九月只适用于手工模式的限制。

上游 `src/app/api/portal/models/[...path]/route.ts` 直接转发 new-api `/api/pricing` 的响应。广场按 `enable_groups` 和 `usable_group` 展示，不执行上述 Portal 目录校验。直接替换会绕过这层筛选；是否在当前生产实际多出模型，尚未读取生产快照比对。

适配要求：Portal 目录仍决定展示范围，new-api 元数据只能补充已匹配模型的介绍、能力和真实性能信息。不能自动复活 Portal 已下架模型、猜测渠道归属或发布内部渠道标识。实际请求继续由 new-api 路由。

注意：当前浏览目录自身没有按 `allowed_tier_keys` 过滤，也固定读取平台租户目录；该白名单目前主要在 Key 页面和创建接口执行。不能将“广场展示客户可用分组”误写成既有目录授权行为，也不能因为广场显示某模型就放宽建 Key 或调用权限。

### 2. 默认摘要价格不同

当前 `catalog-price-summary.ts` 选择模型所属的默认档次，否则使用一个明确命名的实际档次；不把跨组最低价当作当前客户价。

上游 `features/pricing/lib/model-helpers.ts` 的 `getDisplayGroupRatio` 在未选择分组时取最低有效倍率，缺倍率时回退 1。直接采用会改变摘要含义。

适配要求：保留广场分组筛选，默认展示明确分组、规格与单位的报价。以后若要展示“最低价”，应作为另一个明确标注来源及适用条件的展示选项，不能替代当前报价。

### 3. 客户专属价及失败、缓存语义不同

上游 #566 已使登录客户的 pricing 请求携带客户身份，并按 new-api user ID 分开服务器缓存。这项能力可以继承，不能误称上游只支持公共价。

但上游会在会话读取异常时转为匿名报价，服务端缓存新鲜期 60 秒、网络失败可返回 10 分钟内旧缓存，客户端 pricing query 的 staleTime 为 5 分钟。当前浏览目录不缓存报价，专属价的映射或基准倍率不可验证时返回错误。

适配要求：认证查询失败不能静默变成公共报价；客户端和服务端缓存按身份及报价版本隔离，价格发布/专属倍率改变后要可见。初次实现优先沿用现有不缓存报价语义，性能指标可独立缓存。若采用 new-api 有效倍率读取，要核对与当前 Portal 专属倍率记录、真实结算的对应关系，不能重复乘倍率。

上游现有代理测试验证了身份头、匿名隔离和缓存，以及“会话错误降为匿名”的行为，但没有证明本项目生产 new-api 版本和客户凭据一定返回期望的有效倍率。改变该失败策略时，应明确记录测试语义变化并增加保护当前策略的回归。

### 4. 复杂价格与货币换算必须适配

当前目录保存结构化人民币报价，覆盖 token 阶梯与缓存、图片 token/分辨率、视频每秒/每次、跨午夜折扣和客户倍率；缺价显示未定价或拒绝不确定数据。

上游具有动态表达式、任务单位和价格详情能力，但普通价格路径使用 `model_ratio * 2`、分组倍率及独立货币配置，固定价缺失会使用 0。两边输入单位不同，不能把已经换算好的人民币价再次当作 new-api 原始比例计算。

上游 `runtime.ts` 使用 `NEXT_PUBLIC_API_BASE_URL` 并带旧域名/品牌默认值，默认 runtime 为 price=7、USD 汇率=7、quota=500000、USD 展示；status 获取失败会使用默认。LLmRoute 使用自身公开 API 配置，并区分技术计价单位和真实汇率。这些差异需要显式转换；未读取生产 status，不能断言现在一定存在某个固定倍数的价格错误。

适配要求：价格由现有服务端规则生成结构化报价，广场价格组件读取明确单位和适用条件；避免反推虚假的倍率或表达式。上游另有“标准/充值”价格切换，应按本项目实际充值规则决定保留方式，不能默认增加一套本项目没有的折算价。API 示例统一使用 LLmRoute 的公开地址和客户模型名。

另外，审查发现广场部分动态详情计算使用 `groupRatio[group] || 1`，会把合法零倍率当作 1，而卡片工具保留零倍率；普通价格排序还只比较基础价。接入时要补零价卡片/详情一致性以及所选分组实际价格排序回归。

### 5. 两个入口与代码来源

当前 `/models` 与 `/workspace/models` 共用 `ModelsCatalog`，需要一起接入新的展示组件。仅替换公开 page、删除旧 models-browser 会留下工作区入口依赖问题。SDK 的 `/v1/models` 使用另一套机器目录模块；此次广场展示改版应保留其当前映射、价格详情和报价版本行为。

上游 #558 引入 `src/vendor/newapi-web` 并同时更换 LICENSE、声明 AGPL-3.0-only。采用代码时需单列来源、版权声明和许可证处理，不能把模型广场视为纯 CSS 替换，也不能在本报告中认定已完成许可事项。这里仅记录仓库文件事实，不作法律结论。

## 建议实现边界

```text
Portal 当前目录、分组与结构化报价 ─┐
                                  ├─ Portal 广场数据适配 ─ 上游广场展示组件
new-api 匹配模型的介绍/性能元数据 ──┘

客户生成请求 ─ Portal API ─ new-api（继续路由与计费）
```

- 优先保持上游组件组织，通过小范围数据入口和价格渲染适配接入；不在 Portal 新建模型路由器。
- 卡片、表格、详情和排序使用同一份明确分组报价，不能分别使用不同计算来源。
- 模型介绍、能力、图表与性能数据只展示可核验字段；来源不可用时显示缺失状态，不生成性能或能力事实。上游卡片性能查询按模型汇总、详情可含多个分组，需映射并过滤 Portal 档次；模型汇总不能标为所选档次的性能保证。
- 动态表达式、媒体规则不能无损表示时保留完整已有详情或显示不支持；不能降级成单一最低价。
- 保留当前 Key 权限、计费、充值和渠道配置，广场交互本身不扩大这些权限。

## 实施验收条件

1. 匿名、普通客户、专属倍率客户分别对比新旧目录；启用、隐藏、下架和无有效归属模型范围一致。
2. 默认分组、切换分组、同模型多个分组、缺价、零倍率、免费项和无匹配分组都有明确且一致的显示。
3. 同一报价在卡片、表格、详情、排序及价格页一致；客户 A/B 与匿名态不能串价，身份查询失败不能显示错误的公共价。
4. 覆盖完整 token 阶梯、缓存读写、图片各分辨率、图片 token、视频秒/次和跨午夜折扣；使用真实配置的只读快照验证单位换算，不发起收费请求。
5. 调整报价和专属倍率后刷新可见；禁止将过期报价无提示展示为当前客户价。
6. `/models` 与 `/workspace/models` 桌面和手机可用；API 示例为 LLmRoute 域名和正确客户模型名；品牌、货币初始化失败不使用旧站点兜底。
7. 验证 Key 创建权限、真实模型列表鉴权等既有边界不因广场改版放宽；模型广场网络行为不产生配置写入或生成请求。
8. 正式集成仍需完成三方语义审计、上游回归保留检查、typecheck、lint、完整测试及构建，再按项目发布流程处理。
