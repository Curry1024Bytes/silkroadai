# 定价闭环：GPT-5.5 企业档阶梯与缓存计费

日期：2026-09-17（北京时间）。本报告记录本次实现、已取得的隔离验证证据，以及正式发布验收。北京时间 10:06 已发布，10:09 线上核验通过；本次没有代用户发布生产价格。

## 问题与最终行为

此前定价页已能查询基础参考价、计算充值比例和售价倍率，并保存成本草稿，但发布器只支持普通倍率与部分按次价格。GPT-5.5 在 new-api 中使用 `tiered_expr`，且包含缓存读取价格，因此用户完成填写后仍被“特殊计费规则”拦住，不能从同一页面完成预览与发布。

本次接通已有成本草稿到完整阶梯发布流程：保存或选择草稿，预览全部档位、缓存读取和客户专属倍率的影响，确认后创建持久发布任务。任务分别核对 new-api 管理配置、独立 MySQL 持久配置、匿名运行价格，再在同一 PostgreSQL 事务中保存完整目录价格并标记“已生效”。不能完整表示的公式会给出具体限制，不再把未知公式当作普通输入/输出单价发布。

new-api 继续负责实际扣费；Portal 负责报价、经确认后发布配置，以及经过核验的目录展示。没有修改 new-api 源码，也没有在 Portal 另建模型路由或替代 new-api 的动态结算。

这些基础数字还没有乘上游 1.3。不能把已经乘完的 6.5 / 39 / 0.65 再乘 1.3。充值兑换只作用于上游额度换算，客户人民币余额不需要再除以 10。

当前 new-api 公式为：

```text
len < 272000 ? tier("base", p * 5 + c * 30 + cr * 0.5) : tier("tier_2", p * 10 + c * 45 + cr * 1)
```

公开企业组倍率为 0.16。该草稿预览出的客户单价如下，单位均为人民币元 / 百万 token：

| 完整输入长度             | 输入 | 输出 | 缓存读取 |
| ------------------------ | ---: | ---: | -------: |
| 小于 272,000 token       |  0.8 |  4.8 |     0.08 |
| 大于或等于 272,000 token |  1.6 |  7.2 |     0.16 |

完整输入长度包含缓存输入。先选中一个档位，再让整次请求按该档位计费；不是只把超过阈值的部分加价。预览会保留原阈值、比较符号、档名和各档相对价格，不把两档压成一档。

本次只读核对还发现一个企业组专属倍率 0.18。专属倍率替代公开组倍率，基础档为 0.9 / 5.4 / 0.09，长输入档为 1.8 / 8.1 / 0.18。预览单独列出这类影响，不会擅自修改客户专属倍率。

当前 new-api 运行价格已经与上述 1.6 售价目标一致。因此用户确认这条草稿后，预期任务仅完成两端核验并补齐 Portal 的完整阶梯目录，不发送重复改价请求。若之后改成其他售价倍率，则按目标首档绝对价格与当前实际首档价格之比缩放整份公式；重复发布相同目标不会再次乘倍率。
