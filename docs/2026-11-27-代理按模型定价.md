# 代理按模型定价（拆分计费分组）

状态：进行中

## 背景

白标代理 P1 的定价粒度是「代理 × 档次（计费分组）」：代理在 `/partner/pricing` 给每个档次设一个零售率，该档次下所有模型共用一个倍率。代理需要能对个别模型单独定价，例如「SD官转」分组里某个视频模型卖更高或更低，其余模型保持原价。

new-api 的倍率优先级是 `GroupUserRatio` → `GroupGroupRatio[用户分组][计费分组]` → `GroupRatio[计费分组]`，**没有模型维度**。同一模型要在不同客户处卖不同价，只能让它的计费分组不同。因此做法是：把需要单独定价的模型拆成一个独立的 new-api 计费分组，代理对这个新分组单独设零售率。

关键前提（已核对代码）：

- 分组是全局的，与代理数量无关。N 个代理对同一模型各定各的价，仍是 1 个分组、N 行 `GroupGroupRatio`。拆组数量只取决于「需要单独定价的模型数」。
- new-api 的 `ModelRatio` / `ModelPrice` / `billing_expr` 都是按模型全局配置，**不随分组变化**；分组只乘 `GroupRatio`。所以拆组不需要复制模型价格，只需要给新分组设一个 `GroupRatio`。
- `ChannelGroupTopology` 允许一个渠道同时属于多个档次，但**要求共享渠道的所有档次都是镜像档**（有 `upstream_synced_at`）。模型拆分档因此必须按镜像档登记。
- 令牌支持 `group: 'auto'` + `auto_groups` 多分组（`src/lib/customer-pricing/token-binding.ts` 已有实现），一个客户 Key 可以覆盖多个计费分组。
- 目录价按「模型 × 档次」一行，`snapshotCatalog` 以档次在模型 `upstream_map` 里的映射为准，拆分档只会产出一个模型的价格行。

## 范围

只做「按需拆分」：超管对白名单里的模型手动执行拆分，不给全量模型做自动拆分。

- 首发白名单：视频与生图模型（本就是单独 SKU 的），例如 Seedance 系、SD官转下的视频模型。
- 一个模型同一时间只能存在于一个分组：拆分即从原档次 `upstream_map` 移除、加入拆分档，不能两边都留（否则路由和计费不确定）。
- 拆分是平台级操作，影响所有代理；拆分后所有已开放原档次的代理自动获得拆分档的一行价格（默认等于原值），价格不变，代理再单独调整。

## 方案

### 数据模型

- `ChannelGroup` 新增：
  - `kind String @default("standard") @db.VarChar(16)`：`standard` | `model_split`
  - `parent_key String? @db.VarChar(80)`：拆分自哪个档次
- 拆分档规则：
  - `is_default = false`，且不得被选为默认档（拓扑校验拒绝）。
  - 不出现在客户 Key 的档次选择列表（`listCustomerTierGroups` 过滤 `kind = 'model_split'`）。
  - `upstream_map` 只含被拆的模型，`newapi_group` 为新分组。
- migration：给 `channel_groups` 加两列，默认值兼容现有行。

### new-api 侧（运营步骤，代码不代劳）

1. 在 new-api 后台新建计费分组（如 `SD官转_seedance2`），在**原渠道**的 `group` 列表追加该分组（渠道不复制、key 不变）。
2. 在 `GroupRatio` 给新分组设基础倍率：默认与 `GroupRatio[原分组]` 相同；若该模型要卖不同的基础价，在这里设。
3. 确认 `UserUsableGroups` 包含新分组（否则客户令牌校验会拒绝该分组）。
4. 跑 `pnpm tsx scripts/rebuild-channel-model-mapping.ts <channel_id> --apply`（渠道改动后必须）。

### Portal 侧

1. **拆分档登记**：new-api 新增分组后，`syncChannelGroupsFromNewApi` 本来就会建一条 disabled 候选行。管理端加「登记为模型拆分档」的动作：把该行设为 `kind = model_split`、`parent_key`、`enabled = true`、`is_default = false`，并写入只含该模型的 `upstream_map`；同时从原档 `upstream_map` 移除该模型（同一事务，避免模型同时挂两档）。
2. **客户 Key 覆盖拆分档**：客户 Key 改成 `group: 'auto'` + `auto_groups = 该客户可用的全部计费分组`（标准档 + 对该代理开放的拆分档）+ `cross_group_retry: false`。
   - 建 Key（`/api/portal/keys` POST）时按 `listCustomerTierGroups(tenant_id)` 计算分组集合。
   - 存量 Key 一次性迁移：遍历客户 active Key，把 `group` 改为 `auto`、`auto_groups` 写入集合；沿用 `migrateUserKeysToTier` 的「写后回读 + 失败补偿」模式。
   - 拆分档的 `newapi_group` 必须出现在客户 Key 的 `auto_groups` 里，模型才能被路由到新分组并命中 `GroupGroupRatio`。
3. **价格初始化**：拆分事务里为每个已给父档设过价格的代理写两行：
   - `PartnerGroupPrice(tenant, 拆分档 key)`：`wholesale_ratio`、`retail_ratio` 复制父档当前值。
   - `PartnerWholesaleRatioHistory` / `PartnerRetailRatioHistory` 各追加一行，保证拆分前的调用仍按父档历史结算。
   - 拆分档的 `CatalogPrice`：复制父档该模型当前价。
   - 若某代理父档未设零售率（未开放），拆分档也不写零售率，保持不可见。
4. **定价页同步**：`/admin/pricing` 的定价发布已按档次写 `GroupRatio` 双键；拆分档作为一档参与。`ModelRatio` 不动（全局按模型），只给拆分档写 `GroupRatio`。
5. **结算**：不改代码。结算按日志 `log.group` → 校验该代理在该时刻的零售率历史；拆分档的 `group_key` 是新档次 key，历史行在拆分时已写入。
6. **价格展示**：`loadPartnerPriceDisplay` 已按开放档次过滤与缩放，拆分档设了零售率就会在 `/pricing`、`/models`、`/v1/models` 多出一列；`display_name` 需清晰（如「SD官转·单模型」）。

## 运营步骤（拆一个模型）

1. new-api：建分组、渠道追加分组、`GroupRatio` 设基础倍率、确认 `UserUsableGroups`。
2. 跑 `rebuild-channel-model-mapping.ts --apply`。
3. Portal：镜像同步生成候选行 → 管理端「登记为模型拆分档」（父档、模型、显示名）。
4. 核对：拆分档的 `PartnerGroupPrice`、两本历史、`CatalogPrice` 已按父档初始化；原档 `upstream_map` 已移除该模型。
5. 跑一次存量 Key 的 `auto_groups` 迁移（或新客户直接生效）。
6. 验收：代理站发一次该模型请求 → new-api 日志 `using_group` 是拆分档 → `user_group_ratio` 等于代理拆分档零售率 → 结算行 `group_key` 是拆分档。

## 风险与验证

1. **`auto_groups` 的计费取组行为是命门。** 必须先验证这版 new-api：`group: 'auto'` + `auto_groups` 的令牌请求模型时，实际计费分组是命中的那一组，且 `GroupGroupRatio[用户分组][命中分组]` 生效（看日志 `using_group` / `selected_group`、`user_group_ratio`）。不通过则退回备选：拆分档单独建 Key（客户在 Key 页多一个档次选项），或 Portal 注入倍率请求头 + `billing_expr`。
2. **模型不能同时挂两个分组。** 拆分事务必须原子移动 `upstream_map`，否则同模型两组路由不确定、价格随机。
3. **拆分档必须在 `UserUsableGroups` 里**，否则建 Key 被拒（new-api 令牌分组校验）。
4. **拓扑共享渠道依赖镜像标记**：拆分档必须由镜像同步登记（`upstream_synced_at` 非空），手工行会被 `duplicate_channel_owner` 拒绝。
5. **拆分瞬间的存量 Key**：迁移完成前，原档 Key 调不到被拆走的模型（new-api 会 503 no available channel）。迁移窗口内对该模型短暂不可用，需在低峰执行并提前公告。
6. **代理未设拆分档零售率**：拆分档对代理客户不可见（规则 1）。拆分初始化必须复制父档价格，否则模型对所有代理客户消失。
7. **结算历史**：拆分时补写两本历史行，保证拆分前调用按父档、拆分后按拆分档结算。

## 测试计划

- 单元：拆分事务（`upstream_map` 原子移动、价格/历史初始化、白名单校验）；`listCustomerTierGroups` 过滤拆分档；`auto_groups` 建 Key 的分组集合。
- 集成：模拟 new-api（mock）走一遍拆分 → 建 Key → 结算，断言 `group_key` 与历史取值。
- 手工：在测试 new-api 上按运营步骤拆一个视频模型，验证 `using_group`、`user_group_ratio`、结算行、退款冲减。
