# new-api 目录同步：开发与验收（2026-09-11）

已在 `dev` 实现统一的「同步 new-api → 预览变化 → 选择并确认」流程，尚未发布。
模型管理和渠道分组使用同一同步弹窗。后端只读取 new-api，确认后在 Portal 内原子保存；
不修改 new-api 源码、渠道、令牌或计费选项。

## 用户操作

1. 在 new-api 配好分组、启用渠道和模型。
2. 在 Portal 的「模型管理」或「渠道分组」点击「同步 new-api」。
3. 对照档次、渠道、模型映射和价格的前后变化，选择需要同步的项。
4. 新档次和模型默认保存为停用候选；需要启用或上架时额外勾选。
5. 确认后刷新列表。配置改变、预览超过 10 分钟或结果不明时，必须重新预览。

已有价格变动默认不勾选；缺失且能准确换算的价格可直接选择补齐。
不可判断的分组归属、多个候选替换渠道、已删除/停用渠道和无法表达的计费方式会列出提示，
不会猜测配置、删除历史或自动售卖新模型。模型列表存在不能代替真实调用验收。

新建或停用档次启用后，需要再预览一次，为**已经上架的模型**补充该档映射；
当前不把停用档次自动挂到已上架模型上。全新的模型可以与停用档次一起保存为候选。

## 解决的问题

- 旧导入从渠道 `model_ratio` 取价，但当前实际计费配置使用全局
  `ModelRatio` / `CompletionRatio` / `ModelPrice` 和精确的 `GroupRatio`。
  新流程统一读取全局数据，缺配置不默认为 1 或免费。
- 手动新建与后台发现新档次共用 ASCII key 生成器；key 可以留空，放在高级设置中。
  中文、长名称使用稳定 hash 后缀并处理冲突；已有中文 key 不改名。
- 必填项或 key 错误按字段反馈；渠道 ID 必须是正整数，`13x` 不再被解析为 `13`。
- 模型页旧导入弹窗已移除。旧 `/api/admin/models/import` 接口及其既有回归保留兼容，
  页面改走 `/api/admin/newapi-sync`；旧接口不代表本次新同步的取价和确认语义。

## 同步规则

| 内容     | 规则                                                                                  |
| -------- | ------------------------------------------------------------------------------------- |
| 数据源   | 完整分页读取渠道；一次读取五项白名单配置；完整渠道/设置对象不返回浏览器               |
| 归属     | 优先保留有效的现有唯一归属；新渠道只有分组唯一时才自动登记；歧义时提示核对            |
| 模型     | 保留客户模型名、展示名和已有别名；唯一且覆盖原模型的渠道才能提出映射替换              |
| 替换     | 档次登记与所有受影响模型映射一起确认，包括停用模型；缺模型则阻止相关变化              |
| 新增     | 档次、模型默认停用；不会复活现有停用项；启用和上架需额外选择                          |
| 缺失     | 提示受影响项，保留档次、模型、价格历史与客户 Key；需要下架时到对应管理页面处理        |
| 价格     | 全局价格换算后写 Portal 新版本，保留历史和成本；不调用 new-api 写接口                 |
| 差异     | 已有价变化默认不选；明确零价可用；负数、无效值、精度下溢和金额溢出均拒绝              |
| 特殊计费 | 不凭模型名推断计费依据；按次 chat / 按 token 图片等当前目录无法准确表达的情况留待核对 |
| 固定 SKU | `gpt-image-2-{1k,2k,4k}` 不被通用模型价格覆盖，现有 ¥1 / ¥1.5 / ¥2 保留               |
| 未来价格 | 已有未来生效版本时不插入竞争版本，提示先核对定价计划                                  |
| 上架     | 档次启用、渠道有效、当前价完整且计费方式一致；普通模型目录价须与所读实时价一致        |

## 确认与失败处理

- 签名预览绑定租户、Portal 状态、上游元数据、价格换算配置和预览内容，有效期 10 分钟。
- 确认前重新读取 new-api；在 `Serializable` 事务内重新读取 Portal 状态和校验签名。
- 写入前再次检查有效期，覆盖等待网络或事务期间跨越到期时间的情况。
- 关联操作按集合校验，允许渠道登记与模型映射互相依赖；不可只提交半个替换。
- 模型、档次或价格任何一项写入失败，整个 Portal 事务回滚；并发冲突要求重新预览。
- 第一次确认改变数据库状态后，旧签名失效，重复确认不能重复追加价格版本。
- 接口仅限 superadmin，所有数据按目标租户查询；错误不回传原始凭据、设置或数据库信息。
- 远端状态与本地数据库不是分布式事务：签名依据确认时重新取得的上游快照，不能保证
  上游在最后一次读取后永不变化。后续同步会重新检测；没有回写远端来“修正”上游。

## 当前线上配置的只读预演

使用 SSH 隧道只读读取 new-api，以 PostgreSQL `BEGIN READ ONLY` 取得目录快照，
在本地用生产换算值 `NEWAPI_QUOTA_PER_USD=500000`、`USD_TO_CNY_RATE=1` 运行新计划。

- 快照：7 个 new-api 渠道，6 个可见分组；Portal 6 个档次、29 个模型、5 个价格版本。
- 可提出补齐 **30 项模型 × 档次价格**；5 项已有价格保持不变，6 个档次归属无需修改。
- `Nano Banana 2` / `Nano Banana Pro` 的现有目录类型与按次计费方式需核对，未自动填价或改变类型。
- 已失效的模型映射、已停用且无映射的目录行会单列提示；不会因此删除历史。
- 默认选择不包含任何启用或上架。没有执行确认写入、真实模型生成、支付或密钥轮换。
- 原始白名单元数据、只读快照、预演结果和测试日志保存在本机
  `/tmp/llmroute-catalog-sync-20260911/`；快照和元数据文件为 0600。
