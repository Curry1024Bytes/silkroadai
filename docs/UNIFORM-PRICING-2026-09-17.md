# 按倍率发布统一售价（2026-09-17）

## 需求纠正

operator 明确：了解上游动态计费不等于要求 Portal 继承阶梯。客户售价只按填写的基础报价、充值比例与售价倍率计算，不能随上下文长度切换。此前 `bf312e6` 保留阶梯的发布策略不符合这个需求，本次改正。

- 参考成本 = 基础报价 × 上游倍率 ÷ 每元到账额度。
- 客户单价 = 基础报价 × 售价倍率 ÷ 每元到账额度。
- 上游 1:10、倍率 1.3，售价倍率 1.6，基础输入 5、输出 30、缓存读取 0.5：参考成本为 ¥0.65 / ¥3.9 / ¥0.065，客户所有输入长度统一为 ¥0.8 / ¥4.8 / ¥0.08（每百万 token）。
- 成本是所填报价的估算，不声称覆盖供应商实际账单的全部策略。实际业务价格仍需管理员预览确认发布，部署代码不自动改价。

## 实现与兼容

新增 V4 `uniform_token` 发布意图，按输入、输出、缓存读取各自的绝对目标售价生成不含 `len` 条件的固定表达式。借用 new-api 原生表达式引擎，无须修改 new-api 源码；只写一个表达式选项，不切换模式或改变公共/客户专属分组倍率。相同上游模型名的所有关联组影响均在预览中列出，专属倍率仍替代公共倍率。

V1/V2 普通价格任务保持；旧 V3 已存任务按原意恢复，不能被新逻辑解释为统一定价。新旧预览签名不兼容，旧页面需刷新预览。保留来源、成本版本、持久写意图、未知写入禁止重放、管理 API/只读数据库/匿名运行配置三方核验。只有核验成功才写目录并完成任务。

目录继续使用兼容的 `billing_details` 结构，统一价格是一条没有长度上下限的记录；公开价格、后台当前价及历史准确显示“统一单价”。旧阶梯历史继续如实展示。新工作台显示统一目标价格，现有旧价格折叠为对比信息，不要求用户选择阶梯。

本次无 migration、环境变量、依赖、Nginx 或 Cloudflare 修改。针对现有文本表达式模型；未扩展复杂媒体公式、缓存写入或其他未安排功能。
