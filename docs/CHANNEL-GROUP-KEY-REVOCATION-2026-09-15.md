# 分组删除同时撤销客户 Key

## 范围与授权

operator 明确选择「一并撤销它的 key」，并有「做好并测试通过后直接上线」的持续发布授权。本批在 dev 实现；main 保持上游镜像，生产仅部署 prod 的 fast-forward 结果。

本批把以后分组删除改为：预览所属客户 Key → 保存删除任务 → 在 new-api 撤销并核验 → 清理 Portal 分组与模型关联。此前 operator 已删除的「GPT-特惠反代」遗留 Key 是否也执行真实撤销，另有范围问题待答复；发布功能不等于执行这批历史凭据删除。

## 最终行为

- 每把 Key 都核对客户持久授权、new-api 用户 ID、token ID 与实际 group。只处理明确属于所选分组的客户 Key；其他档、其他租户和内部系统 token 不在删除范围。遗留档不能冒用另一个启用档已占用的 group。
- 管理面 DELETE 后再次读取记录，并用不计费的 `/api/usage/token/` 验证旧凭据已被拒绝。HTML 200、鉴权失败、超时、缓存仍接受凭据均不能算撤销成功。已经开始的推理请求不在管理删除接口的取消保证内。
- new-api 的 token 管理 API 按 owner 限定查询；可信 Portal 持久绑定可作为历史 owner 证据，因为正常 new-api 创建用新 ID、更新不允许改 owner/key、删除为软删除。对记录已缺失的历史 Key，还须验证客户身份及凭据拒绝，独立计入「原已失效或不存在」。不把单独 401 或 Portal disabled 当作永久删除证明。
- 任务和每 Key 处理状态持久化；每次 resume 只处理一把，页面自动接续已确认任务。GET 状态和列表不撤销 Key。刷新、进程中断、远端成功但本地 SQL 失败后均可恢复；未知结果不会冒充成功。
- 停止任务会保留分组和模型关联，已撤销 Key 不会恢复。活动 worker 或尚未确认的远端删除意图禁止停止释放锁；已确认的部分完成项和从未发出 DELETE 的失败项可以安全停止后重新预览。
- 全部 Key 核验成功后，原子清理该档模型关联；仍有 B 档关联的模型继续上架，无其他档关联的模型软下架。价格、成本历史、用户余额、客户权限和倍率保留。旧 DELETE 入口如发现任何历史 Key，也要求走带预览的撤销任务。

## 并发与恢复

复用现有数据库协调锁。新建客户 Key 与注册/OAuth 首枚 Key 从远端创建到本地保存持有同一锁，删除任务只能在其提交后取得完整清单。事务失效或操作超过安全期限后，不允许继续发出创建请求或暴露未保存的凭据。B 档新建 Key 在 A 档任务待恢复时仍可进行。

待完成删除任务冻结目录修改和价格发布；任务自己的状态更新与最后清理显式排除自身。客户 Key 迁组同样参与协调，每次远端更新和本地保存前重新校验，避免撤销快照和迁组互相覆盖。new-api 原生管理后台没有 Portal 的协调锁；执行期间不要在另一入口并行改同一批 Key，后台每次删除前仍会重新核对实际归属。

注册和 OAuth 本地写入失败时，先结束并回滚 SQL 事务，再用已知 new-api 用户身份补偿并清理初始 Portal 用户。建 Key 失败不再按别名猜测并删除其他同名 Key。迁组前进限时 60 秒、补偿保留到 90 秒；本地档次更新与协调锁使用同一事务，SQL 失败通过 SAVEPOINT 恢复后补偿，未知结果明确要求核验。平台历史 null 租户与平台 UUID 的客户 Key 一并纳入，其他租户保持严格隔离。

## 数据库与发布影响

新增 migration `20260916010000_add_channel_group_retirement_jobs`，两张任务表为 additive，无历史回填、余额修改或现有 Key 自动撤销。任务表仅存身份元数据、凭据摘要与进度，不保存原始 Key 或客户管理令牌。无依赖、环境变量、new-api 源码、Nginx、Cloudflare 修改。

发布要求生产备份克隆库真实执行 78→79 migration，再迁移生产并切换单 Portal。未完成撤销任务或未知 DELETE 结果禁止回滚至不理解这些任务的旧应用。回滚镜像不会恢复已经撤销的 Key，不得通过数据库回档掩盖远端结果。

MySQL 备份继续读取已有 SELECT-only 配置账号，显式使用 utf8mb4；数据库二进制 SHA、CLI 解码后的 UTF-8 SHA 和只读驱动 SHA 交叉核验，避免上次 latin1 快照的有损问题。

## 操作与恢复

在「渠道分组」点目标分组的「删除」，核对Key和模型清单；默认档需选择替代档，然后确认。页面逐项撤销并核验，全部完成才清理分组。刷新或关闭后，可从「删除任务与遗留 Key」查看并继续未完成任务。

此前已删除的「GPT-特惠反代」可从同一入口单独预览遗留Key。本次仅发布功能，尚未代operator执行该批历史Key撤销。停止任务不会恢复已撤销Key；存在远端结果未确认时应继续核验，不得强行删除任务记录或回档掩盖结果。
