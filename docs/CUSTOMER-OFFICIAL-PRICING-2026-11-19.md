# 客户官方价专属倍率

本次仅完成本地实现与验证。没有部署、修改线上价格或调用真实供应商。

## 价格含义

客户专属价直接按「已确认官方价 × 客户倍率」计算。模型规则优先于客户分组规则；没有新规则的模型继续使用此前的公开价或已有旧客户倍率。新规则之间不叠乘，也不再乘公开分组倍率。

例如官方价为 ¥100／百万 token：

| 适用对象           | 配置                    | 最终单价 |
| ------------------ | ----------------------- | -------- |
| 普通客户           | 公开售价为官方价 × 0.3  | ¥30      |
| 专属客户，分组规则 | 官方价 × 0.2            | ¥20      |
| 上述客户的指定模型 | 模型覆盖为官方价 × 0.15 | ¥15      |

官方基准必须覆盖该模型全部计费规格，包含输入、输出、缓存、长上下文档位或视频矩阵。可以使用已保存的视频官方矩阵；其他基准由管理员确认币种、汇率、单价和来源。公开售价不会自动被当成官方价。

一个模型的全部计费规格必须能够用同一个原生倍率表达；基准缺失、比例不一致、目录别名或渠道归属有歧义时，拒绝发布，要求先核对配置。

## 管理端与用户端

入口为「客户管理 → 客户详情 → 客户专属价」：选择分组，选择整个分组或单个模型，填写官方价倍率，预览逐规格金额，再确认保存。取消模型规则后回到客户分组规则；取消最后一条新规则后保留原有价格语义。

预览显示官方基准、修改前金额、目标金额、实际金额，以及成本可靠时的毛利。成本未知时显示未知，避免用分组采购倍率推断每个模型的利润。已有旧版客户倍率保留为只读记录。

模型广场、模型价格详情、价格表和 API Key 页面显示醒目的专属标识，例如「专属倍率:0.2x」。分组和模型覆盖分别标注；仅部分模型有专属规则时，Key 页面提示「部分模型单独定价」。客户响应不包含采购成本、内部计费分组或渠道凭据。

## 实际计费与历史数据

- new-api 源码保持不变。Portal 将官方价规则转换为 new-api 原生用户倍率，并准备每模型的内部计费分组与来源渠道副本。实际模型选择和扣费仍由 new-api 执行。
- 官方任务插件渠道支持静态 API Key：复制前后核对官方非敏感凭据摘要，真实 Key 始终保留在 new-api 服务端。封装的网页登录凭据不能安全克隆，发现账号、登录或到期标记时拒绝发布；复制丢失凭据时暂停副本，不迁移客户 Key。
- 每个模型使用一个内部自动分组。数量超过 new-api 当前上限时，仅通过带恢复记录的配置写入提高至所需数量；发布失败按记录恢复，并拒绝覆盖其他操作的新值。
- 只调整目标客户、目标分组的 Key 绑定，保留 Key 字符串、预算、有效期、模型限制和其他分组用途。新建 Key 和隐藏的内部 Key 使用同一绑定。
- 内部分组不会被公开模型目录或分组同步误认成新公开分组。
- Seedance 的 Portal 计费路径冻结官方参考来源及版本、客户规则及版本、最终单价和折扣。余额预估、任务记录和完成结算复用同一快照，之后改价不重算旧任务。
- 普通同步文本计量对精确匹配的内部模型组、来源副本及模型归属，使用日志中已经发生的 quota 金额；不按当前客户规则重算延迟日志，也不改写已落库账单。
- **Portal 的普通日志计量不能接管原生异步媒体结算**：new-api 可能分别写预扣、补扣和 type=6 退款，而现有计量轮询只取 type=2。此类内部媒体日志保持未匹配，不能用单条消费日志冒充最终费用。当前 new-api 计费模式的原生余额扣费与任务结算不依赖此计量接管。

指定渠道、引用已有草稿任务及 remix 可能绕过原生自动分组，专属绑定暂时拒绝这些操作。普通参考图片、参考视频 URL 可继续使用。

## 发布失败与恢复

发布记录和不含密钥的操作前后快照先持久保存，再执行远端修改。发布过程回读核对；发生不确定状态时阻止继续消费和改价。管理端显示未完成记录，并提供「核验并恢复」。恢复先检查提交状态，已经提交的操作不能被误回滚；未提交的操作按持久记录恢复。

公共基础价更新会同步重新计算内部客户倍率，使客户的官方价倍率保持原意。若只改变视频官方基准、又调整公开折扣令原生系数不变，而该基准仍有客户规则依赖，则拒绝保存；需先撤销受影响的客户规则，确认新基准后重新发布。只修改采购折扣不受这一限制。

恢复遇到配置已被其他操作修改时拒绝覆盖，保留待核验状态。直接在 new-api 后台修改由 Portal 管理的内部组、渠道副本或倍率，仍可能造成漂移，需先完成核对再恢复使用。
