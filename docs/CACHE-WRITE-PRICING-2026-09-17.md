# 缓存写入统一定价修复（2026-09-17）

## 问题与范围

GPT-5.6 Sol 的现有表达式包含 `cc` 缓存写入费用。旧工作台能够试算和保存成本，但统一价格发布器拒绝包含此变量的公式，导致选择模型后出现“当前向导尚不能完整报价”，无法完成发布。

本次补齐缓存写入报价、预览、确认、持久任务、配置写入与回读核验。客户继续使用统一单价，不按输入长度分档。代码发布不自动修改客户价格，价格仍由管理员核对预览后确认发布。

## 实现

- 新统一定价任务采用 V5，独立处理输入、输出、缓存读取、缓存写入和 1 小时缓存写入；只写既有表达式字典，保留模型其他配置和公共/客户专属分组倍率。
- 当前公式使用的缓存类别在表单标为必填，缺少报价会给出具体字段提示。显式零与缺失严格区分；缓存变量即使系数为零，也影响 new-api 对普通输入 token 的归一，不能删除零项。
- `cc` 是通用缓存写入类别，在 Claude 语义下对应普通/5 分钟写入；`cc1h` 单独处理。工作台使用通用“缓存写入”标签，1 小时字段仅在实际需要或有报价时出现。
- 参考价查询保留两类缓存写入报价，不将缺失当作零，不用 1 小时报价替代普通写入报价。售价仍按 `基础价 × 售价倍率 ÷ 每元到账额度` 计算。
- `cache_write_1h` 为可选 JSON 字段且没有默认值，旧成本数据、旧签名指纹不插入新字段。V3/V4 历史任务继续按各自旧生成器重建，不能被静默转为 V5。
- 发布前重新核对成本版本、模型映射、影响分组和计费配置；发布后核对持久配置和运行时公式，完整核对缓存价后才激活 Portal 目录。失败与不确定写入继续使用原有恢复机制，不盲目重放。
- V5 预览中的旧公式若仅部分分档使用某缓存变量，将缺项显示元数据按实际引擎语义记为有效零；原公式和历史任务保持原文。页面继续隐藏旧长度档价格对比。

## 发布约束

本次没有数据库 migration、依赖、环境变量、Nginx 或 Cloudflare 变更，不修改 new-api 源码。按 `dev → prod → VPS` 发布，仅重建 Portal。

上线前使用新鲜备份和只读计费快照，保留管理员已发布的 GPT-5.5 V4 历史，不能采用旧“任务数量为零”的基线。候选容器通过独立 GET 白名单代理访问真实 new-api，保存/预览仅在隔离 PostgreSQL 副本中进行，不对真实 new-api 确认发布。

回滚旧镜像前必须先停写并检查没有 V5 任务或新增 `cache_write_1h` 成本数据；有新格式数据时应修复前进，不能让旧代码误读新任务，也不能恢复数据库抹掉用户的业务操作。
