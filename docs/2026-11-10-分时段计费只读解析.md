# 分时段计费只读解析（DeepSeek 高峰/非高峰）

> 状态：进行中
>
> 日期：2026-11-10。起因：operator 问 DeepSeek 两个模型为什么同步不进 Portal 目录。

## 1. 需求

new-api 渠道 14（aipg，分组 `DeepSeek`，GroupRatio 0.7）的 `deepseek-v4-flash`、`deepseek-v4.1-flash` 用按北京时间分高峰、非高峰的 `tiered_expr` 公式计价。Portal 目录同步把它们列在「计费规则无法同步」，所以 `/pricing` 和模型广场没有这两个模型，客户看不到价格（能调用，扣费正常）。

需求：Portal 能读出这种公式，在公开页展示两档价格和高峰时段。改价仍在 new-api。

## 2. 原因

不是 new-api 版本问题。生产 `8c02661` 能编译并按公式扣费：2026-11-06 周五 09:04 的两条渠道测试日志 `matched_tier: peak`，实扣 24 / 11 quota，与「(p×单价 + c×单价) ÷ 10⁶ × 分组倍率 0.12 × 500000」逐条一致。

读不了的是 Portal 自己的解析器 `pricing-tiered-expression.ts`：它是白名单，只认 `len <= N ? tier(...)` 按输入长度分档，遇到 `now()`、`date()`、`weekday()`、`hour()` 整条拒绝，避免展示错价。

## 3. 方案

新增只读解析器 `src/lib/admin/pricing-time-token-expression.ts`，与 2026-11-06 的 Seedance 矩阵同一思路：按形状白名单，不在请求上执行公式。

- 接受：可选的一个 `let x = now();`，然后 `条件 ? tier(...) : tier(...)`。条件只能由 `weekday("Asia/Shanghai")` / `hour("Asia/Shanghai")` 与整数、`now()` 与 `date("…带偏移…")` 比较，用 `!`、`&&`、`||`、括号组合。两个 `tier(...)` 交给原长度分档解析器读，单价语法完全一致。
- 拒绝：`minute()`/`month()`/`day()`、其他时区、长度条件、分支内再分档、三档及以上、恒成立/恒不成立的条件、同名档位、不带偏移或不存在的日期、未知函数、多余规则。
- 时段推导：在每个 `date()` 边界之间取一个代表时刻，把条件放在 7 天 × 24 小时的合成网格上求值，得出每周时段；与最后一段（长期有效）不同的日期区间记为例外。`weekday()` 按 new-api 运行时的 Go `time.Weekday`（0 = 周日），已在 `new-api-custom-full/pkg/billingexpr/run.go` 核对。

目录新增 `billing_details.mode = 'time_token'`：两档单价、北京时间每周时段、日期例外。展示：

- `/pricing`、模型广场、同步预览：两档单价 + 「周一至周五 09:00–12:00、14:00–18:00」；已过去的例外（2026 国庆）不再显示。
- 一行摘要与标量列取较贵的一档（高峰），不会少报价格。
- 定价页 `/admin/pricing` 对这类模型只读（标为「分时段计费」），`readBasePrice`、`planModelWrites` 一律拒绝保存，因为保存基础价会把整条分时段公式覆盖掉。运行时核对改为比对公式原文。

## 4. 与方案的偏离

无。DeepSeek 公式里写死的 2026-10-01 至 10-08 国庆例外已过期，展示时自动隐藏；aipg 调整节假日时只需在 new-api 更新公式后重新同步目录。
