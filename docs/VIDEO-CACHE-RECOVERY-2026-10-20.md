# 视频缓存取回（2026-10-20）

客户打开 `video-v2-特价版` 的结果链接时收到 404。生产任务实际为 `SUCCESS`、进度 100%，没有失败原因，但本地 MP4 不存在，缓存补偿已尝试 13 次。

## 原因

上游返回 `api.kkone.vip` 下的公开视频缓存地址，该地址跳转至 `video.kkone.vip`。new-api 按渠道源站为初始请求附加了渠道凭据，因此安全下载器以 `credentialed video cache request cannot redirect across origins` 拒绝跨域跳转。视频已生成，下载失败使本地公共缓存入口返回 `Video cache is not available`，Portal 将其保留为 404。

另查到 3 条同样受影响的已有成功任务：1 条 `video-v2-特价版`、2 条 `MiniMax-H3`。

## 本次取回

对这 4 条任务逐条核对 `SUCCESS`、渠道 8/9、上游任务标识、原媒体地址及下载错误中已观察到的 HTTPS 跳转目标。仅接受同一路径 `/video-cache/{upstream_task_id}.mp4`，且没有查询参数、用户信息或片段的已知媒体地址。

备份原字段后，用带原值条件的 SQL 将这 4 条任务的 `private_data.upstream_result_url` 改为已观察到的最终公开媒体地址。渠道源站仍为原 API 域名，因此 new-api 既有逻辑会对跨源媒体下载清空 Authorization，继续执行原 SSRF 校验和缓存流程。实际下载仍通过 new-api 的内部公共缓存入口进行；没有关闭其安全保护，也没有修改 new-api 或 Portal 应用源码。

- 4 条存量视频均成功取回；内部分段读取均为 `206/video/mp4`。
- 4 条公网链接 HEAD 均为 `200/video/mp4`，大小分别为 2,626,131、2,715,684、3,861,622、1,966,896 字节。
- 本次没有提交新的模型生成任务，没有重新生成或调用收费生成接口。

## 范围与后续

本次修复的是上述已有任务的媒体源数据，没有修改全局下载逻辑。上游新任务若仍返回同样的跨域跳转，仍可能出现同类缓存失败；不能把本次取回宣称为后续任务的永久修复。长期应由上游返回最终公开媒体地址，或在经单独审阅的新-api 版本中支持不会泄露凭据的公开媒体跳转。本次继续遵守不修改 new-api 源码的项目约束。
